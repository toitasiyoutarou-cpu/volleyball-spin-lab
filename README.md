# SPIN LAB — バレーボール回転解析 v1.2

**HTML・CSS・JavaScriptだけの、端末内で解析する研究用アプリです。**
`index.html` 1ファイルで動作します。外部ライブラリ、API、データベース、バックエンドはありません。

実装は完了していますが、**実写での測定精度とiPad Safari実機の動作は未検証**です。合成データでの成功は、実写の精度保証ではありません。

## v1.2：回転推定・VFR・自動復帰の改善

最初は、**開始フレームで円を1つ保存し、「自動復帰」をオンにしたまま解析**してください。初期位置以外の手動指定は、必要になった場合に追加します。自動復帰できなければ従来の修正・再開操作が使えます。

### 回転軸の推定

- 通常の球面モデルが不安定な場合、中心・直径を固定した補助モデルを試します。逆向きの画像照合、内側と外側の模様による別々の推定が一致した場合だけ採用します。
- 隣接フレームの変化が小さい、または推定が失敗する場合、2・4・8枚離れた画像を照合します。角速度は実際の時刻差で割り、別の間隔の推定とも照合します。
- 回転速度が一定でなくても、回転軸自体が安定している場合があります。30組以上・65%以上の画像ペアと、時間を3分割した区間で軸の方向を別途確認し、条件を満たせば**軸だけを採用**します。回転数は独立に判定して保留できます。
- 模様が見えないなど、どの方法でも根拠が不足する場合は数値を表示しません。失敗理由ごとに「次の操作」を表示し、不採用ペアの主な理由も確認できます。

中心の移動方向を回転軸に置き換えることはありません。精度は撮影条件に依存し、補助推定が全ての実写で成功する保証はありません。

### 可変フレームレート（VFR）

MP4/MOVの各フレームの提示時刻を使い、画像ペアの実時間差から角速度を計算します。周期検証もフレーム番号の差ではなく、実時間の遅れで比較します。比較時刻の間にある**特徴量**は線形補間しますが、動画画像や回転ベクトルを生成して欠落フレームを埋めることはありません。

- 保存FPS欄のVFR数値はフレーム間隔の中央値から求めた参考値です。回転数の計算に一定FPSとして代入しません。
- 時刻間隔の中央値の3倍を超える空白は特徴量の補間対象から外します。有効な比較範囲不足、大きい最大時刻差、模様の周期の曖昧さがあればHzを保留します。
- 「元動画・実時間再生」か、撮影・編集条件から確認できた「一定のスロー倍率」を使います。**VFRでは撮影FPSと保存FPSの比からスロー倍率を推定する設定を使えません。**
- VFRと途中で再生倍率が変わるスロー編集は別です。後者の実時間への復元は未対応です。

### 追跡の自動復帰

1. 外周検出の不足や不自然な位置・半径の変化を検出します。
2. 予測位置の周囲を再探索し、前フレームからの模様の変化を順方向・逆方向で確認します。
3. 復帰できなければ、後続の解析対象6枚以内、実時間0.06秒以内を調べます。後続2枚で輪郭の継続を確認できた位置と、直前の位置の間を**実時刻に沿って補間**します。
4. 補間した円についても模様の品質と回転の整合性を確認し、元の停止フレームを読み戻してから解析を続けます。フレームを飛ばしたり二重に登録したりしません。
5. 長い遮蔽、画面外、模様の欠落、競合する候補がある場合は停止し、手動修正・区間変更を案内します。

位置予測は直近6枚の移動速度の中央値を使い、1枚の誤検出が次の予測を大きくずらしにくくしました。自動復帰は初期設定でオンです。オフにすると手動復帰で確認できます。

CSVの `tracking_method` は `manual` / `interpolated` / `auto` / `auto-reacquired` / `auto-bridge` を区別します。`recovery_from_frame`・`recovery_to_frame` で補間の根拠となる前後フレーム、`rotation_method`・`rotation_lag_frames` で回転推定の方法と画像間隔を確認できます。

### VFRのテスト動画

同梱の `tests/synthetic-vfr.mp4` は約240fpsの間隔を不均等にした**合成動画**です。256×256px・240枚、回転数5Hz・軸60°。開始フレーム0の中心は `(128, 128)`、直径144px、終了は239、時間設定は「元動画・実時間再生」です。元から不均等な提示時刻を持つので、VFRとして検出されることを確認してください。

## v1.1：追跡が止まったときの復帰

この版では、同じフレームに複数の位置候補を保存できます。候補は上書きされず、新しく保存した候補が「使用中」になります。**解析するボールは1つで、各フレームにつき1つの候補を使用します。** 複数のボールを同時解析する機能ではありません。

1. 外周の追跡が止まり、自動復帰でも解決できなかった場合、プレビューは**失敗したフレーム**を表示します。別のフレームを表示していたら「停止フレームを開く」を押します。
2. ボールの中心をタップし、直径を外周に合わせます。円をドラッグして微調整できます。
3. **「この位置を保存して再開」**を押します。そのフレームに新しい候補を追加して使用し、停止フレームから再試行します。
4. 候補を比較するには「この位置を候補として追加」で保存し、リストの「使用する」で切り替えます。「保存済みの位置で再開」で続けられます。「削除」はその候補だけを消します。
5. 同じ条件で同じ失敗を繰り返す場合は再計算せず、必要な修正を表示します。**同じ円をもう一度保存するだけでは、模様のぼけや不足は改善しません。**

正常に処理済みのフレームは保持します。停止フレームを飛ばすことや、再開時に二重に数えることはありません。処理済みの過去フレームの候補、解析範囲、時間設定、追跡方法を変更した場合は、整合性のため開始から再解析します。再開のために追加した未来の候補は、保持済みのフレームをさかのぼって変更しません。過去の円もずれていた場合は、そのフレームにも候補を保存して開始から解析してください。

### 円を直しても止まる場合

| 表示される原因 | 次の操作 |
|---|---|
| 外周が背景と区別できない | 保存したフレームでは手動の円をそのまま使います。隣のフレームでも止まる場合は、下記の補間モードを使います。 |
| 手動の円でも模様の品質不足 | 拡大表示でパネルの線を確認。中心・直径が正しいのにぼけている場合は、鮮明な別の区間や元動画に変更します。 |
| 元動画上で直径40px未満 | 実際のボールが十分大きい区間を選びます。円だけを広げて判定を通しても解析精度は上がりません。 |
| ボールが画面から欠けている | 「停止の直前を終了にする」で区間を短くします。48枚未満になる場合は、開始を前に移すか別の区間を選びます。 |
| 動画のフレーム読み出しに失敗 | 「停止フレームを開く」を試します。開けなければ動画を選び直します。古いプレビューを誤って位置保存できないようにしています。 |
| 一時停止・画面が非表示になった | ブラウザを前面に戻し「保存済みの位置で再開」を押します。 |

### 背景との境界が弱い区間：補間モード

1. 「ボール位置の決め方」を **「指定位置の間を補間（外周探索なし）」** にします。
2. 開始フレームと、最後に解析するフレームの位置を保存します。不足する場合はアプリが該当フレームへ移動して案内します。
3. 間でも円がボールに合うように位置を追加します。指定した中心と半径の間を直線で補間するため、急な軌道変化や拡縮には細かい指定が必要です。
4. 解析後はフレームを送って、**区間全体の円を目視確認**してから追跡確認にチェックを入れます。

補間モードは外周の自動探索を使いません。回転数や回転軸を位置の移動から求めることはなく、従来通りボール内部の模様から推定します。模様のコントラスト・鮮明度・回転モデル・周期・時刻の判定は維持しています。手動／補間／自動の区別はCSVの `tracking_method` に記録し、手動・補間の境界スコアは未測定として空欄になります。

既存リポジトリの **`index.html` ファイルの中身を、この版の内容に置き換えてください。** 新しいリポジトリや `index.html` というフォルダーを作る必要はありません。GitHub Desktopを使っている場合は変更をコミットしてPushします。公開ページを再読み込みし、画面上部の **「研究・実験用 v1.2」** を確認してください。この配布ファイルはGitHubへの反映前です。

## GitHub Pagesで公開する

1. GitHubでリポジトリを作成します。
2. ルートに **`index.html`** を追加します。ファイルをアップロードしても、内容をそのままコピペしても使えます。ビルドやnpm installは不要です。
3. **Settings → Pages → Build and deployment → Source: Deploy from a branch** を選びます。
4. **main / (root)** を指定して **Save**。
5. GitHubが表示する公開URLを、iPadのSafariで開きます。

この設定手順は[GitHub公式説明](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)に基づきます。公開用に必要なのはHTMLだけです。選択する実写動画をGitHubに追加する必要はありません。この納品物をまだGitHubへ公開してはいません。

### iPadの「ローカル」の意味

- 解析自体はブラウザ内で完結します。動画は送信されません。
- GitHub PagesはHTMLを届ける静的配信にだけ使います。解析サーバーではありません。
- iPadの「ファイル」アプリからHTMLを開くと、JavaScriptを実行しないプレビューになる場合があります。そのためSafariで公開URLを開く方法を推奨します。
- 画面を開いた後の解析はネットワークを必要としません。ただしブラウザのキャッシュを含め、**完全オフラインでの再起動は保証しません**。Service Workerは使っていません。
- ページを閉じると動画・解析結果・位置指定は消えます。必要な結果はCSVで保存してください。

## 実写の操作

1. **動画を選ぶ**：可能な限り未編集の元ファイルを使います。
2. **区間を設定**：ボールが手から離れた後、遮蔽がなく、画面内にある短い区間を選びます。フレーム番号は0始まり。終了フレームは、間隔の刻みに一致する場合に含みます。
3. **ボールを指定**：開始フレームで中心をタップして直径を合わせ、「この位置を候補として追加」。ドラッグで中心の微調整もできます。
4. **時間を確認**：次節の設定を確認し、チェックを入れます。
5. **解析**：1回48〜720枚。フレーム間隔は原則1。間隔を広げるほど回転の取り違えリスクが増えます。
6. **追跡を確認**：解析後、フレームを送って追跡円が合うことを確認。ずれているフレームに位置指定を追加し、再解析します。自動モードでは保存した円を優先し、その他のフレームで外周を探索します。補間モードでは外周探索を行わず、指定した円の間を補間します。
7. **結果を表示**：追跡確認チェックを入れます。品質条件を満たさなければ、その項目は数値を出しません。軸角だけが採用され、Hzが保留されることもあります。
8. **CSVを保存**：採用値、棄却理由、時間設定、追跡座標、フレームごとの診断値を保存します。

Safariを前面にしたまま解析してください。画面が非表示になったら一時停止します。中止ボタンも現在のフレーム処理後に一時停止し、再開できます。

## 時間基準を間違えない

**「撮影240fps」と「保存動画240fps」は同じとは限りません。** ブラウザの画面更新頻度も、動画fpsの測定には使いません。

| 入力 | 選ぶ設定 | 変換 |
|---|---|---|
| 未編集240fpsを実時間で再生 | 元動画・実時間再生 | 1倍 |
| 全240撮影フレームを保持し、30fpsで再生 | 全撮影フレームを保持したスロー動画、撮影240 | 8倍 |
| 全240撮影フレームを保持し、60fpsで再生 | 同上 | 4倍 |
| 一定の4倍スローと分かっている動画 | 一定のスロー倍率を指定 | 4倍 |
| 途中で再生速度が変わる／フレーム補間・重複がある | 未編集の元動画に変更 | 確定不可 |
| 240fps撮影からコマ落としした30fps実時間動画 | 元動画・実時間再生 | 1倍。ただし高速度解析には不適 |

倍率を `再生秒 ÷ 実時間秒` と定義し、**実時間 = 再生時間 / 倍率** とします。「全撮影フレーム保持」はフレームが本当に保持された場合だけ選んでください。書き出しによる補間・重複を完全には自動判別できません。

MP4/MOVの時刻表から取得できるのは保存された動画のサンプル時刻です。撮影時の実時間はそれだけでは保証できません。読み出しフレームは [requestVideoFrameCallbackのmediaTime](https://developer.mozilla.org/en-US/docs/Web/API/HTMLVideoElement/requestVideoFrameCallback) と照合します。単にリアルタイム再生しながらCanvasを60回/秒読み取る実装ではありません。

## 実装前の実現性判断と採用仕様

| 検討項目 | 判断と実装 |
|---|---|
| 240fps単眼動画の回転数 | 模様が見え、時間基準が正しければ条件付きで可能。球面ワープの角速度と自己相関周期を照合する。 |
| 2次元回転軸 | 中心の軌道では推定しない。正規化した球面のRGB模様がどう移動するかを当てはめる。 |
| 3次元回転軸 | 可視半球の幾何を仮定して3成分を当てはめることは可能。ただし奥行き成分は参考表示のみ。3D測定精度は保証しない。 |
| HTML + JavaScript | File/Blob、video、Canvas、TypedArray、Blob Workerだけで実装。依存ライブラリなし。 |
| iPad Safari | OffscreenCanvasやWebCodecsを必須にせず通常のvideo/Canvasを使用。実機のコーデック・seek挙動・速度は未検証。 |
| 期待精度 | 条件依存で、実写の誤差幅をまだ提示できない。合成試験結果はTEST_REPORT.mdを参照。 |
| 撮影改善 | カメラ固定、明るい環境、短い露光、十分なボール径、元動画、少なくとも2周期、接触・遮蔽なし。 |

### 画像解析の流れ

1. 初期位置は手動指定。開始位置のほか、途中の位置も保存可能。
2. 自動モードでは前フレームの運動または指定点間の補間を予測値にし、40方向の外周の色差を使って中心・半径を局所探索。保存したフレームでは手動の円を使用する。補間モードでは選択中の円の間を補間する。
3. 各フレームの球を96×96pxに正規化。24→48→96pxの3段階で画像の位置合わせを行う。
4. 可視半球を `z = sqrt(1 - x² - y²)` とし、回転ベクトルによるRodrigues回転をRGB画像に適用。
5. RGB輝度残差にHuber型の重みを付け、回転3成分と残留する並進2成分・拡縮1成分を反復推定。外周寄りの不安定な画素は使わない。
6. 行列の条件、画像残差、模様が観測できる方位の広がりを検査。時系列の速度は中央値・MADで外れ値を除外。
7. 小さい変化や失敗時は2・4・8枚間隔を試し、毎3組に1回は採用ペアとは異なる画像間隔で角速度を照合。
8. RGB3群とエッジの空間特徴の時間平均を除き、ラグごとに正規化自己相関。少なくとも2群でピークを確認。
9. 球面モデルの角速度と、自己相関の周期が一致したものだけ採用。短い同等周期がある場合はHzを棄却。
10. 軸角は180°周期の円統計で集約。`atan2(ωy, ωx) mod 180°`。奥行き方向に近い軸は2D角を表示しない。

解析は弱透視投影、球体、固定に近いカメラ、回転数の採用にはほぼ一定の回転を仮定します。軸のみの補助判定では速度の変化を許容します。レンズ歪み、ローリングシャッター、急な視線変化、強い影、球の変形には十分対応していません。

### 信頼度と棄却

信頼度の%は、画像残差、安定性、有効率、周期一致などを組み合わせた**未校正の品質スコア**です。正解確率・信頼区間・誤差保証ではありません。表示上限は95%。数値を表示するかどうかには、スコア以外の必須条件もあります。

主な必須条件：

- 元動画内の直径40px以上。80px以上を撮影時の目安とする。
- 低コントラスト・低いエッジ量・強いぼけを棄却する。ただし画像指標で全てのブラーを検知できるわけではない。
- 回転モデルの有効ペア30組以上、全体の65%以上。
- 各推定ペアの角度が約0.37rad未満。異なる間隔での角速度差18%以下。
- Hzは回転方向と角速度が安定していること。軸のみの補助判定は画像ペア数・時間3区間での方向の一致・画像残差を独立に検査。
- Hzは2周期以上、模様の複数特徴での周期再現、球面モデルとの周波数差12%以内が必要。
- 最長のサンプル時刻差でも回転が推定上0.055回転以下。240fps・間隔1なら約13.2Hzが上限の目安。真の速度に対するエイリアス防止の数学的保証ではない。
- 短周期の似たピークで1回転が曖昧ならHzを棄却。
- 2D軸は画面への投影長が小さい場合や、ばらつきが大きい場合に棄却。
- フレーム時刻の確認、撮影時間基準の確認、追跡の目視確認を必須にする。

### FPS・コンテナの制限

[QuickTimeのstts](https://developer.apple.com/documentation/quicktime-file-format/time-to-sample_atom)を基本に、cttsの提示順、単純なelst編集時間のずれを処理します。mdat（動画本体）はメタデータ読み取りでは開きません。非断片化MP4/MOV・ビデオトラック1つが対象です。VFR（可変フレームレート）は提示時刻に基づく周期検証に対応します。複雑な編集リストや可変速編集は棄却します。

未対応のコンテナでは手動FPSによるプレビューを提供しますが、研究用の結果は採用しません。ブラウザの復号フレーム時刻を98%以上確認できない場合も結果を保留します。取得に失敗したフレームを正しいフレームと見なして処理を確定することはありません。

### メモリと通信

- 動画本体はBlob URLで参照。元動画全体をArrayBufferに変換しない。
- MP4のmoovは32MiB以下、時刻表は600,000サンプル以下に制限。
- 解析区間は最大720枚。元解像度の全フレームを保持しない。
- 過去8枚の96px画像（階層画像も含め約1.2MB）と、小さな特徴ベクトル・数値ログを保持。大きな動画デコードバッファはブラウザ側の管理となり、アプリから上限を保証できない。
- 動画、Canvas、Workerは端末内。fetch、XHR、WebSocket、sendBeacon、アクセス解析、ストレージ保存は使わない。
- Content Security Policyに `connect-src 'none'` を設定。外部スクリプト・フォント・画像も読み込まない。
- 「このHTMLを保存」は初期状態のアプリを保存。選択した動画や解析結果は埋め込まない。
- CSVは明示的に保存ボタンを押した場合だけ端末へ出力する。

## ファイル構成

- `index.html`：公開・利用に必要な全て。
- `README.md`：この説明書。
- `TEST_REPORT.md`：実施した検証と未検証の範囲。
- `tests/synthetic-240fps.mp4`：ブラウザの動画読み込み経路を試す合成240fps動画。
- `tests/fixture-ground-truth.json`：合成動画の正解値。
- `tests/test-engine.cjs`：数値部分の自動検証（開発者用、Node.js）。
- `tests/test-video.cjs`：MP4時刻表・復号画像の検証（開発者用、Node.jsとFFmpeg）。
- `tests/make_fixture.py`：同じ合成動画を生成する補助スクリプト（Python・NumPy・FFmpeg）。アプリの実行には不要。
- `tests/test-recovery.cjs` / `tests/recovery-scenarios.js`：v1.1のエラー復帰操作の検証（開発者用、Node.jsと`@napi-rs/canvas`が必要。アプリ本体には不要）。
- `tests/test-auto.cjs` / `tests/auto-scenarios.js`：自動復帰とVFRのコントローラー試験。
- `tests/test-v12.cjs`：VFRと速度変化を持つ合成画像の数値試験。
- `tests/test-vfr-video.cjs`：VFRのMP4生成・時刻表・FFmpeg復号の検証。
- `tests/synthetic-vfr.mp4`：VFRの読み込みを試す合成動画。
- `tests/*-results.json`：検証ログ。

実写の確認では、元240fps動画、ボールが見えるフレーム範囲、スロー編集・書き出しの有無が分かれば、その条件に対する評価を進められます。
